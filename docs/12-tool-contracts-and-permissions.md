# 12 — Tool Contracts and Permissions

## Principles

- Every tool has typed input/output.
- Authorization is server-side and independent of model output.
- Read tools and write tools are separated.
- Mutating tools are deny-by-default.
- Consequential writes require application-service validation and human authority.
- Tool calls are logged with correlation ID, version, status and latency.

## Approved tools

### `get_claim_context`
Read-only normalized claim/member/provider/policy references.

### `check_policy_active`
Deterministically checks service date against policy-version effective period.

### `check_member_eligibility`
Deterministic eligibility result:
`PASS | FAIL | UNKNOWN` with evidence.

### `check_required_documents`
Compares document inventory against configured checklist.

### `search_policy_clauses`
Retrieves evidence only from authorized/current policy version.

### `evaluate_waiting_period`
Deterministic date calculation.

### `calculate_financial_limits`
Decimal-based limit/sub-limit calculation.

### `find_possible_duplicates`
Searches structured claim history for explainable duplicate indicators.

### `get_risk_signals`
Returns computed anomaly indicators.

### `save_recommendation`
Persists draft reviewer-facing recommendation only; cannot finalize claim.

## Permission matrix

| Tool | Processor | Reviewer | Supervisor | Admin | Agent |
|---|---:|---:|---:|---:|---:|
| get_claim_context | scoped | yes | yes | scoped | yes via service context |
| search_policy_clauses | scoped | yes | yes | yes | yes |
| deterministic checks | scoped | yes | yes | yes | yes |
| save_recommendation | no | no direct | no direct | no direct | yes |
| final review mutation | no | yes | yes | no unless explicitly granted | **never** |

## Tool output rule

No tool returns hidden credentials, raw secrets or unrestricted document URLs.
Signed/authorized document access is generated by application services.
